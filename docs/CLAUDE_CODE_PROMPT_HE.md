# משימת פיתוח ראשונה ל-Claude Code — FLOW FACTORY 3D

פעל כמפתח משחקי Unity בכיר וכבודק איכות. עבוד בתיקיית הפרויקט המקומית שפתחתי או שאפתח איתך. קרא תחילה את `PRODUCT_SPEC_HE.md` שבאותה תיקייה, ולאחר מכן ממש את **גרסת 0.1 בלבד**. השפה לממשק המשחק יכולה להיות אנגלית פשוטה, אך דיווחי התקדמות והסברים אליי צריכים להיות בעברית.

## קדימויות
1. חוויית משחק עובדת באיכות גבוהה, שאפשר להפעיל ב-Windows ולייצא ל-Android.
2. ארכיטקטורה קריאה, קוד מסודר, 12 שלבים בנתונים, שימוש בפרימיטיבים של Unity ללא נכסים בתשלום.
3. ממשק Mobile Portrait, מגע באמצעות מסך ועכבר במחשב, שמירה מקומית, בדיקות תקינות.
4. לא לבצע שום פיתוח של מודעות אמיתיות או רכישות. לא להוסיף SDK, שירות, חשבון או רכיב ענן חיצוני ללא בקשה מפורשת ואישור מתאים.

## סביבת עבודה
- בחר Unity 6.3 LTS עם 3D URP, C#.
- אם Unity Hub / Unity Editor זמינים, בדוק את הגרסה, התלויות והפרויקט לפני כל שינוי. אל תטען שביצעת Build או בדיקת Play Mode אם לא באמת ביצעת.
- אם אין גישה לעורך, צור קבצי C# והוראות הרכבה מפורטות והצהר מפורשות מה לא ניתן היה לאמת.
- אל תשנה קבצים קיימים ללא גיבוי או הסבר; הימנע מפעולות הרסניות.

## היקף משחקיות
- מבט איזומטרי קבוע על גריד מסועים תלת־ממדי.
- סוגי אריחים: ישר, פינה, מקור, יעד. לכל אריח שולי חיבור שמסתובבים ב-90°.
- נגיעה/קליק בסוגי האריחים המסתובבים משנה את האוריינטציה, ללא סיבוב כפול למגע יחיד.
- כפתור 'Run' מחשב מסלול יציב של חבילה ומשגר אותה. אם אין מסלול תקין, מוצג משוב ברור והמשחק חוזר למצב עריכה.
- התנגשות עם אריח ללא כניסה תואמת, יציאה מהלוח או לולאה גורמת לכישלון ידידותי בלבד.
- 12 שלבים ידניים עם לפחות פתרון ידוע אחד; עליה מדורגת במורכבות; הדרכה בשלבים 1–2.
- בעת ניצחון עוברים למסך הצלחה, פותחים שלב הבא ושומרים התקדמות גם לאחר סגירה.
- תפריט ראשי/בחירת שלב, הגדרות צליל, איפוס שלב.

## ארכיטקטורה ובדיקות
- מודל נתונים ל-LevelDefinition כ-ScriptableObject או מבנה נתונים שקול ובר־עריכה.
- הפרדת לוגיקה של אימות מסלול מהצגת המסועים ומהאנימציה.
- בדיקות לפחות לנתיב תקין, נתיב חסום, חוסר חיבור, לולאה, חיבור שגוי, reset, unlocked levels, save/load.
- אסור לבנות 12 סצנות נפרדות כמעט זהות; יש להשתמש בסצנת משחק גנרית הטוענת נתוני שלב.
- אם ניתן, צור כלי Editor שמייצר באופן חד־פעמי את 12 נתוני השלבים ובודק שהפתרון הידוע של כל שלב תקין.
- צור README קצר בעברית ובו התקנה, הרצה ובניית Android APK.

## ביצועים ואיכות
- תצוגה אנכית 9:16, Safe Area, טקסט ברור, כפתורים מותאמים למגע.
- בלי מערכות כבדות: אין צורך בפיזיקת Rigidbodies לכל חבילה או צללים יקרים לכל אובייקט.
- להוסיף תצוגת FPS לבדיקה שמוסתרת מחוץ למצב Debug.
- כוון ל-30FPS יציב במכשיר Android בינוני; בדיקות פיזיות נדרשות כדי לאשר יעד זה.
- קוד C# ללא שגיאות קומפילציה. דווח על בדיקות שבוצעו באמת עם תוצאותיהן.

## אופן מסירה
בסיום ספק:
1. רשימת קבצים וסצנות שנוצרו או שונו.
2. הוראות פתיחה והפעלה מדויקות.
3. תיאור מה עובד ומה עדיין חסר.
4. פירוט אילו בדיקות הופעלו, מה הצליח ומה לא אומת.
5. הוראות ייצוא APK והתקנה על מכשיר Android.
6. הצעה לשיפור המשחקיות בלבד לשלב הבא, לפני הוספת מונטיזציה.

אל תציג אב־טיפוס מילולי בתור משחק בנוי. התחל ליצור את התשתית ואת השלב הראשון העובד, ואז הרחב ל-12 שלבים תוך ביצוע בדיקות.
